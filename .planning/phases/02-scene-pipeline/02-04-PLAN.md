    Inspect the captured kitty frame and run both backends in a real terminal:

    1. KITTY (preferred path) — open the captured `/tmp/dd3_scene.rgba` (or its PNG conversion from Task 2) AND run live in a kitty/ghostty/wezterm terminal:
       `cargo run --release -- --kitty`
       Confirm:
       - Dozens of boxes are visible, arranged as a readable rack/datacenter (grouped clusters), NOT a random pile or a noise of dots.
       - Boxes differ in COLOR (status variety: indigo running, amber paused, gray stopped, cyan restarting, red crashed) and in SIZE (idle boxes are small-but-visible, busy ones bigger but none fills the frame).
       - A near box clearly OCCLUDES a far box (no see-through); depth reads (far boxes dimmer via fog).
       - The orbit runs by DEFAULT, smooth, and the whole rack stays in frame (no boxes popping/clipping at the edges across a full revolution).

    2. BRAILLE (fallback path) — run in any terminal (or force it):
       `cargo run -- --braille`
       Confirm the SAME four things, and SPECIFICALLY watch inter-box ordering: as the camera orbits, far boxes must NOT bleed through near ones (this is the painter's-sort risk the kitty z-buffer doesn't have). Watch for jitter — a box must hold its slot frame-to-frame (no teleporting).
