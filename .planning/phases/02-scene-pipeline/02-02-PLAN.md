  <name>Task 1: render_scene — multi-box braille rasterizer with cross-box painter's sort</name>
  <files>src/render3d/raster.rs, src/render3d/mod.rs</files>
  <action>
    Add `pub fn render_scene(entities: &[crate::world::entity::Entity], view: ViewParams, viewport: (usize, usize), palette: &Palette, config: &RenderConfig) -> Framebuffer` to `raster.rs`, and re-export it from `render3d/mod.rs`. Keep the existing single-cube `render()` (camera/tests still use it) — add, don't replace.

    Reuse the existing supersample buffer + AA-resolve + projector setup from `render()`. The change is the face-collection loop:
    1. Build ONE `Vec<RenderFace>` spanning EVERY box. For each entity, transform the unit cube's 8 vertices by the entity's model transform (translate by `entity.position`, scale by `entity.half_extents * 2` since the unit cube spans +/-0.5 -> a box of side `2*half_extent`). Compute each face's WORLD-space centroid and outward normal (normal is rotation-free here — axis-aligned boxes — so the unit-cube normal is the world normal). Back-face cull per face as today (`normal.dot(eye - centroid) > 0`).
    2. Carry each face's per-box base color: `palette.status_color(entity.status)` (CONT-01). Store it on the RenderFace (extend the struct with a `base: Color` field) so the fill uses the right status color per box.
    3. CROSS-BOX PAINTER'S SORT (the critical correctness step): sort the SINGLE combined face list farthest-first by world-space camera distance to the face centroid. This is what makes a near box occlude a far box — do NOT sort per-box then concatenate. (No per-pixel z-buffer; painter's sort over convex axis-aligned boxes is sufficient per PITFALLS #4. Note any residual cyclic-overlap risk in the SUMMARY for the human-verify in 02-04.)
    4. Fog: compute the distance range across ALL visible faces (scene-wide near/far) so far boxes dim and near boxes stay bright — depth reads at scale. Apply the existing orientation-Lambert + fog shading per face, using that face's `base` color.
    5. Fill each face with the existing barycentric `fill_face` into the supersampled buffer; resolve with the existing `resolve_supersampled` (dominant-color-per-dot, flat faces — keep it).

    Store projected world vertices once per box to avoid re-projecting shared corners 3x. Skip a face if any corner clips (existing behavior); the scene-framing camera (Task 2) keeps boxes in-frustum so this should be rare.

    Tests (headless, no terminal):
    - `render_scene` with a small hand-built 2-entity scene where box A is clearly in front of box B along the view axis: assert the center overlap region resolves to box A's status color, NOT box B's (inter-box occlusion proof).
    - `render_scene` with entities of different statuses yields >= 2 distinct colors in the framebuffer (per-box status color is applied).
    - empty scene (`&[]`) returns an all-unlit framebuffer without panicking.
    - a box far from center still lands inside the framebuffer when framed by a scene-radius view (sanity; can build the view from a literal eye/target).
  </action>
