<objective>
Generalize the KITTY real-pixel renderer (the preferred high-quality path, `src/kitty.rs`) from one centered cube to a whole `World` of boxes. The kitty path already owns a per-pixel z-buffer (`fill_tri` depth-tests NDC z), so — unlike the braille path — inter-box occlusion is essentially FREE: the work is iterating all boxes into the shared depth buffer and coloring each by status. This makes the kitty path the cleanest place to prove the scene reads at scale.

Purpose: Deliver success criteria #1 (dozens of boxes), #2 (status color + load size), #3 (stable slots via 02-01), and #4 (scene-framed orbit) on the kitty backend, in parallel with the braille generalization (02-02). These two plans touch disjoint files (`kitty.rs` vs `render3d`/`ui`), so they run in the same wave.
Output: A multi-box kitty render path (live orbit + RGBA dump) framing the full rack.

  <name>Task 1: render_rgba over a whole World (z-buffered multi-box) + per-box status color</name>
  <files>src/kitty.rs</files>
  <action>
    Change `render_rgba` from rendering one `&Cube` to rendering a whole scene. COMMIT to a SINGLE fog-input mechanism in the signature — pass the scene bounds so the absolute fog range is scene-wide and frame-independent:
    `pub fn render_rgba(entities: &[crate::world::entity::Entity], view: ViewParams, bounds: &crate::world::scene::SceneBounds, palette: &Palette, w: usize, h: usize) -> Vec<u8>`.

    (Rationale for choosing `&SceneBounds` over loose `(near, far)`: 02-01 already produces `SceneBounds { center, radius }`; deriving fog from it keeps ONE source of truth for "where the scene is", and makes the flicker-safe property obvious — the range depends only on the static scene + camera, never on which faces happen to be visible this frame.)

    Keep ALL the existing machinery: the SS supersample buffers, the shared `color`/`depth` arrays, the projector (cell_aspect 1.0 for square pixels), `fill_tri`'s NDC-z depth test, the box-downsample, and `emit_kitty`/`delete_all`/`base64`. The change is the geometry loop:
    1. Build the unit cube once (`unit_cube()`), reuse its faces/normals as the box template.
    2. For EACH entity: compute its model-transformed world vertices (translate by `entity.position`, scale by `entity.half_extents * 2`). For each face: back-face cull against the eye using the WORLD centroid; shade with `face_shade` but using the entity's `palette.status_color(entity.status)` as the `base` (CONT-01) instead of the hardcoded Running color.
    3. Project the face's 4 corners; skip on clip; `fill_tri` the two triangles into the SHARED `color`/`depth` buffers. Because depth is shared across all boxes, the z-buffer resolves inter-box occlusion automatically (near hides far) — this is the kitty path's built-in advantage over braille.
    4. FOG (this is the warning fix — ONE chosen mechanism, reflected in the signature): the current `face_shade` computes its absolute range as `cam_dist +/- CUBE_BOUND` (a single-cube assumption, kitty.rs:122-125). Generalize it to the SCENE using the passed `bounds`: the camera-to-scene-center distance `(view.eye - bounds.center).length()` +/- `bounds.radius`, i.e. `near = (view.eye - bounds.center).length() - bounds.radius`, `far = (view.eye - bounds.center).length() + bounds.radius`. Change `face_shade` (or its caller) to take these scene `near`/`far` instead of recomputing from `CUBE_BOUND`; remove the `CUBE_BOUND` constant. This PRESERVES the flicker-safe "absolute, not per-frame-visible-faces" property (the range is a function of the static scene + camera only) — do NOT revert to a per-frame min/max of visible faces.

    Update the two call sites in this file (`run_kitty`, `dump_rgba`) to pass `&world.bounds`, and the `top_face_shade_is_yaw_invariant` test to the new shape (see Task 2). Keep `render_rgba` deterministic and pure (no I/O) so it stays unit-testable.

    Tests (headless):
    - 2-box scene with box A directly in front of box B: the overlapping output pixels carry box A's status color (z-buffer occlusion proof) — A's color, not B's, and not a blend.
    - different-status boxes -> the output RGBA contains >= 2 distinct non-background colors.
    - empty scene -> all-background RGBA, no panic.
