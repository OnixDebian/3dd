<objective>
Build the `world/` foundation that turns "one cube" into "a synthetic scene of dozens of boxes": entity data, a clamped load->size mapping (CONT-02), a status->color hook (CONT-01), and the load-bearing **network-aware layout algorithm** that gives every box a stable, deterministic slot (CONT-05). Also teach the Camera to frame the whole scene (CAM-01 generalization) so the two rasterizer plans (02/03) can both consume the same bounds without touching each other's files.

This plan RESOLVES the phase's open research decision: rack-grid vs network-grouped-floor. We commit to **network-grouped slots arranged into a rack/datacenter grid** — groups are placed as contiguous regions (future network floor-planes in Phase 4 ENT-01 drop in as the group's plane), and within a group boxes fill a stable row/column grid. This is "designed network-aware from the start" without rendering networks yet.

Purpose: This is the linchpin of the phase. It is pure, deterministic, and TDD-friendly (stable slots and clamped sizing are exact `assert_eq!(fn(input), output)` properties), so it gets its own TDD plan and both rasterizers build on top of it.
Output: A `world` module producing a `World { entities, bounds }` and a `Camera::frame_scene`, all unit-tested.
</objective>

  <name>Task 1: Entity model + clamped load->size mapping (RED-GREEN-REFACTOR)</name>
  <files>src/world/entity.rs, src/world/mod.rs, src/main.rs</files>
  <behavior>
    Create `src/world/entity.rs` defining the domain entity and the size mapping. Register the module in `main.rs` (`mod world;`) and create `src/world/mod.rs` re-exporting the public types.

    `Entity`:
    - `id: u32` (stable identity — the layout key; later maps to a container id)
    - `position: glam::Vec3` (world-space slot center, assigned by layout)
    - `half_extents: glam::Vec3` (per-axis half-size; the rasterizers scale the unit cube by this)
    - `status: crate::theme::Status` (REUSE the existing enum — CONT-01 status->color flows through the existing `Palette::status_color`; do NOT introduce a parallel color/status type)
    - `group: u16` (synthetic network/group id — the layout grouping key; Phase 4 ENT-01 turns a group into a network floor-plane)

    Clamped, compressive load->size mapping (CONT-02, PITFALLS #12). Write `pub fn load_to_half_extent(load: f32) -> f32` where `load` is a normalized usage proxy in `[0, 1]` (synthetic CPU/RAM):
    - Enforce a MINIMUM half-extent `MIN_HALF` (idle is always legible, never sub-pixel) and a MAXIMUM `MAX_HALF` (a hog never fills the frame).
    - Compressive curve between them: use `sqrt(load)` (or log1p) so the heavy tail compresses; map `[0,1]` -> `[MIN_HALF, MAX_HALF]` via the curve.

    Testable cases (write these tests FIRST, watch them fail):
    - `load_to_half_extent(0.0) == MIN_HALF` (idle clamped to the floor, not zero)
    - `load_to_half_extent(1.0) == MAX_HALF` (hog clamped to the ceiling)
    - `load_to_half_extent(-5.0) == MIN_HALF` and `load_to_half_extent(99.0) == MAX_HALF` (out-of-range inputs clamp, never NaN/negative)
    - monotonic: `load_to_half_extent(0.25) < load_to_half_extent(0.75)`
    - compressive: the size gained from 0.0->0.25 is GREATER than from 0.75->1.0 (sqrt curve front-loads) — proves it's not linear
    - result is always finite and > 0 for any f32 input including NaN (guard: treat non-finite as MIN_HALF)
  </behavior>
  <implementation>
    Constants `MIN_HALF` and `MAX_HALF` as named consts in entity.rs (e.g. 0.3 and 1.2 — tune so a full rack reads clearly; exact values are a knob). Guard `load`: `if !load.is_finite() { return MIN_HALF }`, then `clamp(0.0, 1.0)`, then `MIN_HALF + (MAX_HALF - MIN_HALF) * load.sqrt()`. `Entity` derives Debug, Clone, Copy. Keep `entity.rs` pure (no I/O, no rasterizer deps).
  </implementation>
  <verify>cargo test world::entity (or cargo test entity) — all new tests pass; cargo build clean; `mod world;` present in main.rs</verify>
  <done>Entity struct exists carrying theme::Status; load_to_half_extent is clamped, compressive, monotonic, and NaN-safe with passing tests; commits follow RED (test) -> GREEN (impl) cadence.</done>

<task type="tdd">
  <name>Task 2: Network-aware deterministic layout + synthetic scene + bounds (RED-GREEN-REFACTOR)</name>
  <files>src/world/layout.rs, src/world/scene.rs, src/world/mod.rs</files>
  <behavior>
    Create `src/world/layout.rs` with the layout algorithm and `src/world/scene.rs` with the synthetic generator + scene bounds. Wire both into `world/mod.rs`.

    LAYOUT (the resolved research decision — network-grouped rack grid, CONT-05):
    `pub fn layout(group: u16, index_in_group: u32) -> glam::Vec3`
    - Deterministic and PURE: the same `(group, index_in_group)` ALWAYS returns the same Vec3. This is the anti-jitter guarantee — slots are a function of stable identity, never of frame time or iteration order.
    - Groups are laid out as contiguous regions along one axis (e.g. each group gets a Z-band / future floor-plane), so a group reads as a cluster. Within a group, boxes fill a 2D rack grid (columns along X, shelves stacked along Y or rows along Z) with fixed spacing `SLOT_SPACING` that comfortably exceeds `2*MAX_HALF` so even max-size boxes don't overlap their slot neighbours.
    - Network-aware: the grouping is the first-class placement axis (group -> region), exactly the structure Phase 4's network floor-planes need.

    SCENE GENERATOR (`src/world/scene.rs`):
    - `pub fn synthetic_scene() -> World` produces DOZENS of entities (target ~40-60) across several groups (e.g. 4-6 groups). Distribute statuses across the existing `theme::Status` variants (mostly Running, a few Paused/Stopped/Restarting/Crashed) so color variety is visible. Assign each a synthetic load in `[0,1]` (deterministic pseudo-random from id is fine — keep it reproducible). Each entity's `position = layout(group, index_in_group)` and `half_extents = Vec3::splat(load_to_half_extent(load))` (or per-axis if you want non-cubic boxes; cubic is fine for v1).
    - `pub struct SceneBounds { pub min: Vec3, pub max: Vec3, pub center: Vec3, pub radius: f32 }` computed from all entity AABBs (position +/- half_extents). `radius` = distance from center to the farthest corner (bounding sphere) — the camera uses this to frame the scene.

    WORLD (`src/world/mod.rs`):
    - `pub struct World { pub entities: Vec<Entity>, pub bounds: SceneBounds }`. `synthetic_scene()` returns a fully-populated World.

    Testable cases (write FIRST):
    - determinism: `layout(2, 7) == layout(2, 7)` across calls; and two different `(group,index)` pairs map to DIFFERENT positions (no slot collision)
    - no-overlap: for the generated scene, no two entities' AABBs intersect (centers at least `SLOT_SPACING` apart along the grid axes; assert min pairwise center distance >= 2*MAX_HALF)
    - grouping: entities of the same group are spatially clustered — the max intra-group center spread is less than the min inter-group region gap (proves groups form regions, not interleaved)
    - count: `synthetic_scene().entities.len()` is in the "dozens" range (assert >= 30)
    - bounds enclose everything: every entity AABB corner lies within `[bounds.min, bounds.max]`; `bounds.center` is the midpoint; `bounds.radius` >= distance to the farthest entity corner
    - stability across a rebuild: calling `synthetic_scene()` twice yields entities whose id->position mapping is identical (same slots) — the anti-teleport pin
  </behavior>
  <implementation>
    Keep layout a closed-form function of (group, index) — e.g. `cols = ceil(sqrt(group_capacity))`, `col = index % cols`, `row = index / cols`, then `Vec3::new(col*SLOT_SPACING - x_center, row*SLOT_SPACING, group as f32 * GROUP_DEPTH - z_center)`. Center the whole grid near the origin so the existing frustum-safe camera math stays sane. `SLOT_SPACING` const > `2*MAX_HALF` (from Task 1) for the no-overlap guarantee. For synthetic load/status, hash the id (simple deterministic LCG or `id.wrapping_mul(prime)`) — reproducible, no `rand` dependency. SceneBounds: fold over entities tracking componentwise min/max of `position +/- half_extents`.
  </implementation>
  <verify>cargo test world (layout + scene tests pass); cargo build + cargo clippy --all-targets clean; `cargo test` whole suite still green (no regressions to the existing 36 tests)</verify>
  <done>layout() is deterministic, collision-free, and clusters by group; synthetic_scene() yields 30+ status-varied, load-sized entities in stable slots with correct SceneBounds; all pinned by tests.</done>
</task>
