<design_decisions>
PIN these:

- Channel: `tokio::sync::mpsc::unbounded_channel::<DockerMsg>()` (ARCHITECTURE: unbounded is
  fine, low message rate, no `.await` on send in producers). The render side will drain it
  non-blocking with `try_recv` (wired in 03-04). Producers are fire-and-forget.
- DockerMsg enum (typed, bollard-free):
    * `Added(ContainerSnapshot)`     — a container appeared (from list seed or events create/start)
    * `Removed(String)`              — container id destroyed/died
    * `StatusChanged(String, theme::Status)` — pause/unpause/restart/die status transition
    * `Stat(String, StatSample)`     — a normalized stats sample for container id
  (Keep it small; Phase 4 extends it for breathing/detail.)
- Producer tasks in streams.rs, `pub fn spawn_docker_tasks(docker: Docker, tx: UnboundedSender<DockerMsg>)`:
    1. SEED: `list_containers` (all, incl. stopped) -> map each via domain::from_bollard ->
       send `Added`. Then spawn a stats task for each RUNNING container.
    2. EVENTS: subscribe `events()`; on container create/start -> `Added` + spawn its stats
       task; on die/destroy -> `Removed` + CANCEL that container's stats task; on pause/unpause/
       restart -> `StatusChanged`. (Reconcile the live set from events — PITFALLS Pitfall 7.)
    3. STATS (per running container): `stats(id, StatsOptions{ stream:true, .. })`. On a stream
       that already carries precpu per sample, map bollard's response -> the 03-01 `RawCpu`/`RawMem`
       inputs, call `normalize(...)`, send `Stat(id, sample)`. On stream END/ERROR (container
       died) -> do NOT panic: just end the task (the Removed from events handles entity removal).
       NEVER `.unwrap()` a stream item.
    Keep a `HashMap<String, CancellationToken>` (or `JoinHandle`) so stats tasks are cancelled
    when their container dies (no orphan tasks — Pitfall 7). All bollard stream consumption uses
    `futures::StreamExt`/`TryStreamExt` (already a dep). NEVER do CPU work or blocking I/O here
    (Pitfall 8) — this is pure async I/O -> channel.
- STABLE SLOT MAPPING (the CONT-05 guarantee for live, changing containers): the existing
  `Entity.id: u32` and `layout(group, index_in_group)` assume dense small ids. Live container
  ids are strings and the set changes. Decision for LiveWorld:
    * Maintain an insertion-ordered registry: `slots: Vec<Option<String>>` (slot index -> container id)
      plus `id_to_slot: HashMap<String, usize>`.
    * On Added(snap): if the id already has a slot, reuse it; else assign the LOWEST FREE slot
      index (reuse a hole left by a removed container so the rack stays compact) and record it.
    * On Removed(id): free its slot (set to None) and drop the entity; do NOT shift other slots
      (that would teleport every box — the whole point is stability).
    * Group assignment: derive `group: u16` from the container's `group_key` (network name) via
      an insertion-ordered `HashMap<String, u16>` group registry (first network seen -> group 0,
      etc.). Position = `layout(group, index_within_group)` where index_within_group is the
      container's rank among entities sharing its group (kept stable the same lowest-free way),
      OR — simpler and acceptable for this phase — keep a single global slot space and map the
      flat slot index to (group, index_in_group) the same way scene.rs does. CHOOSE ONE and
      document it; the only hard requirement: a given container id keeps the SAME position for
      its whole lifetime regardless of others churning.
    * Entity.id (u32): hash the string id to a stable u32 OR just use the slot index as the u32
      id (slot index is already stable per container) — pick the slot index (simplest, stable,
      and unique while alive). Document the choice.
- Building the World on each reconcile: after applying a DockerMsg, rebuild `entities: Vec<Entity>`
  from the live registry (status from latest StatusChanged/Added, half_extents from the latest
  Stat's `load` via `load_to_half_extent`, default to MIN_HALF / warming-up until the first real
  sample arrives), then `SceneBounds::from_entities(&entities)` (REUSE the existing fn) -> `World`.
  `LiveWorld::apply(msg) -> Option<World>` returns a rebuilt World when the scene changed (the
  render side swaps it in). Empty container set -> a World with zero entities and degenerate
  bounds (the empty-state banner is 03-04's concern; here just don't crash on empty).
- Do NOT change Entity, World, SceneBounds, or layout() signatures. LiveWorld is additive.
</design_decisions>
