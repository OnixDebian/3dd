<design_decisions>
PIN these so the executor does not re-derive them:

- This module is PURE and bollard-FREE. Define plain input structs (e.g. `RawCpu { total_usage:u64, system_usage:Option<u64>, online_cpus:Option<u64>, percpu_len:usize }`,
  `RawMem { usage:u64, cache:u64, limit:u64 }`) inside this module. The 03-03 streaming
  code will MAP bollard's `ContainerStatsResponse` onto these — that mapping (and the
  bollard dep) is 03-03's job, NOT this plan's. This isolation is what lets the
  normalizer be unit-tested with zero daemon and survive bollard API churn
  (ARCHITECTURE Anti-Pattern 4).
- mod.rs OWNERSHIP: 03-01 writes `src/docker/mod.rs` declaring ALL four submodules:
  `pub mod stats;` (created here), and `pub mod domain;`, `pub mod connect;`, `pub mod streams;`
  COMMENTED OUT with a `// added by 03-0X` note, OR (preferred) declare them live only if the
  file exists. Decision: declare `pub mod stats;` now and leave clearly-marked commented stubs
  `// pub mod domain;  // created by 03-02` etc. so 03-02/03-03 just UNCOMMENT their line when
  they add their file — a one-line, non-conflicting edit. (If the executors of 03-02/03-03
  prefer, they may instead add their `pub mod` line; the marker comments tell them exactly
  where.) Re-export `normalize`, `StatSample`, `RawCpu`, `RawMem` from stats.
- CPU% formula (PITFALLS Pitfall 1, authoritative):
    cpu_delta    = cpu_total_usage - precpu_total_usage
    system_delta = system_usage    - precpu_system_usage
    online_cpus  = online_cpus, fallback to percpu_len if None or 0
    cpu_pct      = (cpu_delta as f64 / system_delta as f64) * online_cpus as f64 * 100.0
  Guards (ALL required):
    * If this is the FIRST sample (no prior sample / precpu zero) -> return a WarmingUp
      marker (or load contribution 0.0); the box is NOT sized from it.
    * If system_delta <= 0  -> 0.0 (never divide).
    * If online_cpus == 0   -> 0.0.
    * Clamp final cpu_pct to [0.0, online_cpus * 100.0].
    * Any non-finite result -> 0.0.
- Memory (PITFALLS Integration Gotcha): used = usage.saturating_sub(cache); clamp to
  [0, limit]; mem_fraction = if limit>0 { used/limit } else { 0.0 } in [0,1].
- The NORMALIZED LOAD that drives box size: combine into a single [0,1] value the
  EXISTING `world::load_to_half_extent` consumes unchanged. Decision: load = the MAX of
  (cpu_pct normalized to [0,1] by dividing by (online_cpus*100)) and mem_fraction — so a
  box grows for whichever resource it is hot on. Document this choice in a doc comment.
  Keep cpu_pct and mem_fraction also available on the output struct (03-04/Phase 4 may
  surface them in a HUD/detail panel).
- Output type: a small domain struct, e.g.
    `StatSample { cpu_pct: f32, mem_used: u64, mem_limit: u64, mem_fraction: f32, load: f32, warming_up: bool }`.
  This is the domain stat type the rest of the app speaks (NOT bollard's type).
- Use f64 for the delta math (counters are u64 and large), convert to f32 only for the
  final load/cpu_pct fields.
</design_decisions>
